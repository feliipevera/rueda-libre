MINIRETO 6: JUSTIFICACIÓN DE LOS CONTROLES

1 Tipo de bicicleta: input radio (mismo name="tipo_bicicleta")
   Son solo tres opciones excluyentes y conviene verlas todas a la vez.
   Con el mismo name el navegador permite marcar una sola.

2 Correo: input type="email".
   El navegador comprueba que tenga formato de correo y en el celular muestra
   un teclado con arroba, lo que reduce errores de digitación.

3 Comentarios: textarea.
   Es texto largo y libre; un input de una sola línea no alcanza para esto.

COMPROBACIÓN DE HERENCIA (DevTools, Styles y Computed)
- Se hereda: color. En un <p> el color calculado es rgb(20, 33, 61) (Azul Noche)
  y viene de "Inherited from body"; el <p> no tiene regla propia de color.
  Lo mismo con font-family: Open Sans.
- No se hereda: padding. El body tiene padding 1rem (16px) y el <p> tiene 0px.
  Tampoco se hereda background-color: el <p> es transparente aunque el body es Crema.
- Otro caso: los <a> y los controles del formulario no heredan la fuente ni el color
  porque el navegador les da los suyos; por eso hay reglas específicas para ellos.

MINIRETO 10:

CONFLICTO DE LA CLASE "activo"
Reglas del compañero (con mis variables):
  #menu a { color: var(--gris-asfalto); }
  .activo { color: var(--verde-ruta); font-weight: 600; }

Especificidad (ids, clases/pseudoclases, elementos):
  #menu a  -> (1,0,1)
  .activo  -> (0,1,0)
Causa: un id pesa más que cualquier cantidad de clases, así que "#menu a" vence
a ".activo" aunque ".activo" esté después. En DevTools (Styles), el color de
".activo" aparece tachado. El font-weight sí se aplica porque "#menu a" no lo define.

Solución:
  #menu a.activo { color: var(--verde-ruta); font-weight: 600; ... }
  Especificidad (1,1,1): supera a (1,0,1) por la clase adicional.
Hover/foco del menú ("#menu a:hover", (1,1,1)) van después de ".activo" porque
tienen la misma especificidad y gana la última.

Segundo conflicto evitado: "a:hover" (0,1,1) vencería a ".boton-cta" (0,1,0) y dejaría
el texto azul sobre fondo azul. Se resolvió con ".boton-cta:hover" (0,2,0).

RECORRIDO CON TAB
En index, tarifas y reservas el foco siempre se ve (contorno Azul Noche de 3px).

grid o flexbox y por que :

1 Portada  Grid Usé `grid-template-columns: 1fr 1fr para tener dos columnas iguales (texto y foto) y
align-items: center` para centrar verticalmente el bloque de texto. Elegí Grid porque el layout es de
columnas definidas con proporciones.
2 Galería de rutas  Grid.Usé repeat(3, 1fr) con gap: tres columnas iguales y una separación
uniforme. Grid permite declarar la cantidad de columnas directamente y que todas las tarjetas midan lo mismo.
3 Reservas  Grid.Usé grid-template-columns: 2fr 1fr para la proporción 2:1 entre el formulario y elcontacto. Con
 fr el reparto es exacto y el gap no hace desbordar el contenedor, cosa que sí pasaría con porcentajes.
4 Fila del formulario (documento y celular)  Flexbox.Son solo dos campos en una única fila, es decir, 
una dimensión. Con flex: 1 1 12rem y flex-wrap se reparten el espacio y, si no caben, el segundo baja de 
línea. Grid habría sido más de lo necesario para este caso.
5 Encabezado  Flexbox. El nombre y el menú van en una sola fila, uno en cada extremo (justify-content:
 space-between) y centrados verticalmente (align-items: center). Es una dimensión, y con `flex-wrap` el
  menú baja de línea si no cabe.
6 Pie de página  Flexbox. Los tres bloques (marca, contacto y horario) van en una fila, alineados por 
arriba y separados con gap. Es una sola dimensión y con `flex-wrap` los bloques bajan de línea al estrechar 
la ventana.
